【GIT】从孤立提交（Dangling Commit）恢复误删的源码

【GIT】从孤立提交（Dangling Commit）恢复误删的源码

[toc]

概述：git pull 拉取远程后，本地某个项目的源码被”弄丢”了，工作区只剩 bin/、obj/ 编译产物。本文记录如何通过 reflog + 孤立提交（dangling commit） 找回源码并重新纳入版本控制。

场景还原

某个仓库（此处为 .Net-Code，内含 FunctionPointerDemo、HarmonyDemo 等项目）在 git pull 后：

  • 两个项目的源码文件（Program.cs、csproj、README.md 等）消失，目录里只剩 bin/ 和 obj/（编译产物）。
  • git status 却没有显示这两个目录被删除。

为什么 git status 不显示删除？

因为这两个项目所在的 commit，在 pull 的 fast-forward 合并后脱离了 main 分支的历史，变成了”孤立提交（dangling commit）“。它们的文件对象仍然完整保存在 .git 对象库里，只是没有任何分支引用它们了。

关键概念

什么是 Dangling Commit（孤立提交）？

当提交被 checkout、reset、merge 等操作”跳过去”后，如果没有分支或 tag 引用它，它就变成 dangling。但它不会立即被清除，对象仍保存在 .git/objects/ 中，直到被 git gc 真正清理。因此：

  • ✅ 只要 reflog 还在，就能找回
  • ⚠️ 长时间后或执行 git gc --prune 后，孤立对象可能被永久清除

为什么源码会”丢失”？

本例根因是 fast-forward 合并：pull 时远程历史是本地历史的”超集”，git 直接快进。但这两个项目所在的本地提交（6d2ded6、aab3d12）不在远程分支上，快进后这些提交脱离了 main，工作区对应文件被远程版本覆盖/清理。

常用排查命令速查

目的命令
查看提交包含的文件git ls-tree -r --name-only <commit>
查看提交内容git show <commit>
找回丢失的提交git reflog
某提交在哪些分支git branch --contains <commit>
某提交在哪些远程分支git branch -r --contains <commit>
恢复某目录到工作区git checkout <commit> -- <path>
检查对象是否损坏git cat-file -p <commit>^{tree}
查看所有孤立对象git fsck --lost-found

预防建议

  1. pull 前先 commit：确保本地改动都提交了，避免被快进覆盖。
  2. 用 git pull --rebase 代替默认 merge，减少历史分叉。
  3. 定期 git fsck --lost-found：及时发现并备份孤立对象。
  4. 关键源码尽早推送远程，避免只存在于本地分支。
