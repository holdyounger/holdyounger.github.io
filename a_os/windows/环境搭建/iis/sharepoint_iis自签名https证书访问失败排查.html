三、为什么 IIS 自签名证书不能直接修改 CN

IIS 的“创建自签名证书”功能比较简单：

  • Subject/CN 通常根据当前服务器名称自动生成；
  • 自签名证书由自己签发自己，因此 Subject 和 Issuer 相同；
  • IIS 管理器没有编辑 CN、SAN、Issuer 的功能；
  • 证书创建后不能直接修改字段，只能重新生成或申请新证书。

“证书友好名称”只是证书管理器中的显示名称，不会改变 CN、Issuer，也不会影响证书的实际身份校验。

六、结果

后来更换为 Exchange 生成的证书后访问恢复正常。由此确认，原 IIS 自签名证书的问题重点在于其服务端证书用途/扩展配置不适合当前 HTTPS 场景；同时，使用 FQDN 访问时还必须配置 DNS 或 hosts。Exchange 证书通常带有更适合 IIS HTTPS 的 Server Authentication EKU 和 Key Usage，因此替换后可以正常完成 TLS 握手。

注意：证书字段中的“公用名（CN）”不能替代 SAN。现代浏览器主要根据 SAN 校验主机名，生成或申请证书时应显式配置 SAN。
