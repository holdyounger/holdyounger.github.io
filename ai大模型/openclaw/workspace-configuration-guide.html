核心概念

什么是 Workspace？

Workspace 是 Agent 的家，是 OpenClaw 用于文件工具和 workspace context 的唯一工作目录。

关键区分：

  • Workspace (~/.openclaw/workspace)：Agent 的工作目录，存储记忆、技能、配置等
  • Config (~/.openclaw/)：存储全局配置、凭证和会话数据

重要特性

特性说明
默认工作目录Workspace 是默认的 cwd，工具解析相对路径时基于此
非硬沙箱不是严格的沙箱隔离，绝对路径仍可访问系统其他位置
私有记忆应视为私有记忆，不要公开分享或提交到公开仓库
自动创建运行 openclaw onboard 或 openclaw setup 时自动创建

Workspace 文件结构

核心引导文件

文件用途加载频率
AGENTS.mdAgent 操作指令和内存使用规则每次会话开始
SOUL.md人格、语气和边界定义每次会话开始
USER.md用户信息和称呼方式每次会话开始
IDENTITY.mdAgent 名称、风格和 Emoji每次会话开始
TOOLS.md本地工具和约定说明（不控制工具可用性）每次会话开始
HEARTBEAT.md心跳检查的小型清单（保持简短）心跳触发时
BOOT.md可选的启动清单（网关重启时执行）网关重启时
BOOTSTRAP.md一次性首次运行仪式（完成后删除）仅首次运行

记忆系统

文件/目录用途说明
memory/YYYY-MM-DD.md每日记忆日志每天一个文件，建议启动时读取今天和昨天的
MEMORY.md策展的长期记忆仅在主私有会话中加载，不适用于共享/群组上下文

扩展目录

目录用途说明
skills/工作区专属技能最高优先级技能位置，覆盖项目/个人/托管/内置技能
canvas/Canvas UI 文件节点显示文件（如 canvas/index.html）

引导文件限制

  • 单个文件最大字符数：agents.defaults.bootstrapMaxChars（默认 20000）
  • 总字符数限制：agents.defaults.bootstrapTotalMaxChars（默认 150000）
  • 缺失文件处理：缺失的引导文件会注入”missing file”标记，会话继续

Git 备份与版本控制

为什么需要 Git 备份？

  • 数据安全：Workspace 包含 Agent 的记忆和技能，丢失等于 Agent “失忆”
  • 版本追踪：可回滚到之前的状态
  • 迁移方便：在新机器上克隆仓库即可恢复

迁移到新机器

  1. 克隆仓库到目标路径（默认 ~/.openclaw/workspace）
  2. 在 ~/.openclaw/openclaw.json 中设置 agents.defaults.workspace
  3. 运行 openclaw setup --workspace <path> 补充缺失文件
  4. 如需会话数据，从旧机器复制 ~/.openclaw/agents/<agentId>/sessions/

不要提交的秘密

  • ❌ API Keys、OAuth Token、密码
  • ❌ ~/.openclaw/ 目录下的任何内容
  • ❌ 敏感聊天记录或附件

模式行为

渠道channels.*, web否

环境变量

环境变量来源

OpenClaw 从以下位置读取环境变量（按优先级）：

  1. 父进程环境变量
  2. 当前工作目录的 .env（如果存在）
  3. ~/.openclaw/.env（全局回退）

在配置中引用环境变量

规则：

  • 仅匹配大写名称：[A-Z_][A-Z0-9_]*
  • 缺失/空变量会在加载时报错
  • 转义：$${VAR} 输出字面值
  • 在 $include 文件中也可用

Shell 环境导入

或使用环境变量：OPENCLAW_LOAD_SHELL_ENV=1

最佳实践

1. 保持单一活跃 Workspace

多个 Workspace 目录会导致认证和状态混乱。建议：

  • 仅保留一个活跃 Workspace
  • 不再使用的旧目录归档或删除
  • 使用 openclaw doctor 检测额外的 Workspace 目录

5. 安全共享 Workspace

如需共享 Workspace（如团队协作）：

  • 使用私有 Git 仓库
  • 移除 MEMORY.md 和 memory/ 目录（包含个人记忆）
  • 不提交 .env 和敏感文件
  • 考虑使用 .gitattributes 过滤敏感内容
